Setup for evaluation

Experimental: the current transfer path has known defects. Keep the controller's original data, disable automatic erasure and cleanup, and read the limitations before connecting it.

Hardware

You need a Pi Zero W or Zero 2 W, a 16 GB+ microSD card, a suitable 5 V USB supply, an OTG adapter and a controller data cable. The primary development target is Betaflight logging to internal SPI flash.

Flash and boot

  1. Download a Raspberry Pi image from Releases. Check that the selected release includes an image, and verify it against any supplied checksums.
  2. Flash it using Raspberry Pi Imager or Etcher. On the boot partition, optionally edit logfalcon-config.txt to set SSID and PASSWORD.
  3. Insert the card and power the Pi through PWR IN. Wait for the hotspot; boot timing has not been established for this image.
  4. Join LogFalcon Wi-Fi (default password fpvpilot), then open http://log.falcon or http://192.168.4.1.

Before connecting a controller

Use SSH to edit /etc/logfalcon/logfalcon.toml. Set these values in the existing file:

erase_after_sync = false
storage_pressure_cleanup = false

Check the TOML carefully: invalid configuration can currently fall back to defaults, which enable both behaviours. For manual evaluation, --dry-run also skips erasure. These instructions do not repair the known transfer defects.

The supplied image uses SSH user pi and default password logfalcon. Change it with passwd. SSH and hotspot passwords are separate.

First transfer

  1. Confirm that the FC's Blackbox Device is SPI Flash and that automatic erasure and storage cleanup are disabled.
  2. Connect the controller through the Pi's USB / OTG data port. The installed USB rule starts the transfer service automatically.
  3. Keep the controller connected while copying. Check the service log for the outcome; the current dashboard and LED cannot reliably confirm completion.
  4. Refresh the dashboard, download the saved .bbl, and open it in Blackbox Explorer. Preserve the original controller data during evaluation.
# Follow transfer results over SSH
journalctl -u 'logfalcon@*' -f

When reporting a test, include the Pi model, FC model, firmware, bytes copied, time taken and whether the downloaded file opens correctly.

Download logs

Join the Pi's hotspot and open http://log.falcon. Refresh the saved-session list after a transfer, then choose Download .bbl. Details contains metadata and the manifest; Delete from Pi removes only that stored session.

A saved session is a raw flash dump, which may contain several flight logs. Open it in Blackbox Explorer. Sessions are stored under /mnt/logfalcon-logs/fc_VARIANT_uid-XXXXXXXX/DATE_TIME/, with raw_flash.bbl and manifest.json.

The saved-file checksum compares received bytes with a reread of the saved file. It does not independently verify the FC's source data or prove that the dump decodes correctly.

Compatibility and current limitations

  • Betaflight / SPI flash: the main development target. The code rejects MSP API versions older than 1.41. That version check is not a hardware compatibility guarantee.
  • Transfer defects: large sizes can produce zero-length read requests. Blackbox configuration currently parses the support byte as the storage-device type.
  • iNav: flash-summary parsing needs correction. Treat support as unconfirmed.
  • Unsupported: controller-side SD card logs and ArduPilot.
  • Dashboard: web and sync services run separately without shared live status. Progress, errors and safe-to-unplug state cannot currently be reported here.
  • Hardware evidence: Pi builds exist, but physical compatibility, power-loss behaviour and boot/transfer times require recorded tests.

Report findings through GitHub Issues. LogFalcon is independent of the Betaflight and iNav projects.

Configuration

The installed file is /etc/logfalcon/logfalcon.toml. A supplied --config path is searched first, followed by the system file, local config/logfalcon.toml and defaults. Invalid files can currently be skipped.

# Recommended values for evaluation; current defaults differ
 erase_after_sync = false
 storage_pressure_cleanup = false
 min_free_space_mb = 200
 flash_read_compression = false

Use the dashboard's Settings page to change the hotspot SSID and password. A Wi-Fi restart may disconnect the browser. If saving fails, update the Pi configuration over SSH and inspect the web-service log.

Leave idle_shutdown_minutes = 0 during evaluation: the current web process cannot observe activity in the separate sync process.

See the repository's configuration file for all available settings and their current defaults.

LED reference

The intended patterns are: slow pulse for boot, solid for ready, fast blink for work, a rapid burst followed by solid for completion, and SOS for error.

Current limitation: LED access and persistence need hardware validation. The service restores the ready light after both success and failure. Use the service log to confirm the outcome.

Troubleshooting and administration

Hotspot or dashboard does not appear

Check the power supply and try http://192.168.4.1 while connected to LogFalcon Wi-Fi. Open the address explicitly; automatic captive-portal opening is not guaranteed.

journalctl -u logfalcon-web -n 50
journalctl -u hostapd -n 50
Controller is not detected or transfer fails

Use the Pi's data port and a known data cable. Check whether the controller appears as /dev/ttyACM* or /dev/ttyUSB*. Keep automatic erasure disabled and include the service log in a bug report.

lsusb
journalctl -u 'logfalcon@*' -n 100
SSH and health checks
ssh pi@192.168.4.1
passwd
curl http://127.0.0.1/health

The default SSH password is logfalcon. Health reports information from the web process; an OK response does not establish transfer success.

Installing on an existing Raspberry Pi OS

The repository's scripts/install.sh installs packages, services and an AP-only network configuration. Review it before running it on an existing Pi; it changes system networking.

sudo bash scripts/install.sh

The matching scripts/uninstall.sh removes the installation. A fresh image is the simpler evaluation route.

Development

Requires Go 1.23+. All application code is Go, with a stdlib HTTP interface and embedded HTML templates. No JavaScript framework is required.

git clone https://github.com/proeugene/logfalcon.git
cd logfalcon
make build
make test
make lint     # Requires golangci-lint
make build-pi
make build-pi2

Tests run without hardware. The protocol, FC detection, storage, sync, web, LED and configuration code live in separate packages under internal/. Passing tests and builds do not validate real-device behaviour.

Preview the dashboard locally

mkdir -p /tmp/logfalcon-preview
LOGFALCON_STORAGE_PATH=/tmp/logfalcon-preview LOGFALCON_WEB_PORT=8080 ./bin/logfalcon --web

Open http://localhost:8080. This previews the log browser; it does not emulate a controller, hotspot or live transfer.

Build the image

The image build uses pi-gen in Docker. From the repository:

cd pi-gen
bash build.sh

The tag-triggered release workflow builds Linux ARM6, ARM64 and AMD64 binaries, builds and inspects the image, and checks required release assets. Inspect the workflow result rather than assuming a tag produced a working image.

See Contributing and the release checklist for further details.

CLI reference

logfalcon --web                              # Log browser
logfalcon --port /dev/ttyACM0 --dry-run        # Copy; skip erasure
logfalcon --port /dev/ttyUSB0 --dry-run        # Explicit USB serial port
logfalcon --config /path/to/logfalcon.toml --web
logfalcon --version

A serial transfer requires an explicit --port. --dry-run still copies data and does not disable storage-pressure cleanup; configure that separately.
