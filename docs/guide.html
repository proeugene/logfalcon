Pilot and developer guide

Collect your first flight log

Set up a Raspberry Pi to collect blackbox logs from your FPV drone running Betaflight. Open the saved recording on your phone or computer.

Set up the Pi

For your first copy, keep automatic erasure and storage cleanup switched off. This keeps the original on the controller and your saved recordings on the Pi. Check the two settings.

Hardware

You need a Pi Zero W or Zero 2 W, a 16 GB+ microSD card, a suitable 5 V USB supply, an OTG adapter and a controller data cable. Use a Betaflight flight controller that records to internal SPI flash.

Flash and boot

  1. Choose a version on GitHub Releases and read its notes. Under Assets, look for the SD card image ending in .img.xz. Check its SHA-256 against the digest for that asset before flashing. If your chosen version has no image, build one from its source.
  2. Flash it using Raspberry Pi Imager or Etcher. On the boot partition, optionally edit logfalcon-config.txt to set SSID, PASSWORD and COUNTRY_CODE (for example, GB in the UK).
  3. Insert the card, power the Pi through PWR IN and wait for its hotspot to appear.
  4. On a fresh installation, join the Wi-Fi network named LogFalcon- followed by the device's 12-character ID, or your configured network name. Upgrades keep the existing name. The temporary default password is fpvpilot. Open http://log.falcon or http://192.168.4.1.
  5. If Set up Wi-Fi opens, choose Skip for now to keep your current settings and go straight to Recordings. To change the hotspot details, choose Review Wi-Fi changes, then Save and restart Wi-Fi. Rejoin the hotspot using the details you saved.

Before connecting a controller

Connect over SSH with ssh pi@192.168.4.1. In /etc/logfalcon/logfalcon.toml, confirm both settings have the following values.

erase_after_sync = false
storage_pressure_cleanup = false

New installations default both behaviours to off. Upgrades preserve existing configuration, including previously enabled destructive settings. Invalid configuration stops copying. For a manual transfer, --dry-run copies the recording and skips erasure.

The supplied image uses SSH user pi and default password logfalcon. Change it with passwd. SSH and hotspot passwords are separate.

First transfer

  1. Check that the controller’s Blackbox Device is SPI Flash and that it contains a recording. Stop recording before collection.
  2. Open the dashboard on the Pi’s Wi-Fi. Connect the controller to the Pi’s USB / OTG data port. The copy starts automatically. Keep the controller connected while the dashboard shows progress.
  3. Under Latest transfer, look for Copy completed. Check the saved size and the message Data retained on controller. If the connection drops first, rejoin the Pi’s Wi-Fi and check the result on the dashboard.
  4. Choose Download saved .bbl. Open the file in the Blackbox Viewer in the Betaflight App and select a flight to see its traces. If the app needs internet access, save the file to your phone first and open it when you’re back online.
# Follow transfer results over SSH
journalctl -u 'logfalcon@*' -f

Download logs

To retrieve a recording later, rejoin the Pi’s hotspot, open http://log.falcon and find the controller and collection time under Saved recordings. Use the recording’s download button for a single .bbl, or select up to 100 recordings to download a ZIP with their manifests and notes. The list updates when a copy completes. Use Refresh list to retry.

Why earlier flights appear again

Each copy contains the flash in use at collection time. If the controller kept its data, the next file can contain the same flights plus a new one. The dashboard compares copies from the same controller. Channel details shows which gyro axes a recording header declares. Load the file in the Viewer to inspect the actual samples.

On the Pi, look under /mnt/logfalcon-logs/fc_VARIANT_uid-XXXXXXXX/DATE_TIME/ for raw_flash.bbl and manifest.json. The saved-file checksum compares the incoming bytes with a reread from the Pi’s storage. Opening the file in the Viewer checks that it decodes.

Which controllers work with LogFalcon?

  • Flight controller. Use Betaflight with Blackbox Device set to SPI Flash. LogFalcon blocks firmware below MSP API 1.41 and warns above API 1.48, the highest version checked against the Betaflight protocol. It cannot copy from iNav, ArduPilot or a controller’s SD card.
  • Raspberry Pi. The image targets the Pi Zero W and Zero 2 W. Check the field test record for observations on individual boards and the roadmap for upcoming checks.

Report findings through GitHub Issues. LogFalcon is independent of the Betaflight and iNav projects.

Configuration

The installed file is /etc/logfalcon/logfalcon.toml. An explicit --config path must exist and be valid. Otherwise the system file, local config/logfalcon.toml and safe defaults are considered in order. Invalid files, values and unknown keys stop startup.

# Keep recordings on both the controller and the Pi
 erase_after_sync = false
 storage_pressure_cleanup = false
 min_free_space_mb = 200
 flash_read_compression = false  # compression is unsupported

Use the dashboard's Settings page to change the hotspot SSID and password. A Wi-Fi restart may disconnect the browser. If saving fails, update the Pi configuration over SSH and inspect the web-service log.

Leave idle_shutdown_minutes = 0 to keep the Pi running between flights.

See the repository's configuration file for all available settings and their current defaults.

LED reference

The dashboard and the Pi’s activity LED use the same transfer status. The LED uses a slow pulse for waiting, a fast blink for work in progress and a repeating double blink for a saved copy. A solid light means the controller reported empty flash. SOS signals an error.

Before unplugging, check Latest transfer on the dashboard for the result and saved size. If the light and dashboard disagree, check the transfer service log.

Troubleshooting and administration

Hotspot or dashboard does not appear

Check the power supply and join LogFalcon Wi-Fi. If the dashboard doesn’t open automatically, enter http://192.168.4.1 in your browser.

journalctl -u logfalcon-web -n 50
journalctl -u hostapd -n 50
Controller is not detected or transfer fails

Use the Pi's data port and a known data cable. Check whether the controller appears as /dev/ttyACM* or /dev/ttyUSB*. Keep automatic erasure disabled and include the service log in a bug report.

lsusb
journalctl -u 'logfalcon@*' -n 100
SSH and health checks
ssh pi@192.168.4.1
passwd
curl http://127.0.0.1/health

The default SSH password is logfalcon. Health reports information from the web process; an OK response does not establish transfer success.

Installing on an existing Raspberry Pi OS

The repository's scripts/install.sh installs packages, services and an AP-only network configuration. Review it before running it on an existing Pi; it changes system networking.

sudo bash scripts/install.sh

The matching scripts/uninstall.sh removes the installation. To keep your existing system, flash the LogFalcon image to a spare card.

Development

Use Go 1.27 with the toolchain selected in the checkout's go.mod. The dashboard uses Go's standard HTTP server and embedded HTML templates.

git clone https://github.com/proeugene/logfalcon.git
cd logfalcon
make build
make test
make lint     # Requires golangci-lint
make build-pi
make build-pi2

The tests use a simulated serial connection and temporary files, so you can run them without a Pi. See the test record for runs on physical hardware.

Development diagnostics

Extra protocol metadata is enabled by default (DEBUG=true), with UK Wi-Fi country GB. Shut down cleanly, insert the card into the Mac and copy LOGFALCON-DIAGNOSTICS/latest.json. It contains bounded, redacted recent events, not a complete journal. Abrupt power loss can lose the last events. See the diagnostics and physical acceptance instructions. To reduce logging, set DEBUG=false in the boot configuration and reboot.

Preview the dashboard locally

mkdir -p /tmp/logfalcon-preview
LOGFALCON_STORAGE_PATH=/tmp/logfalcon-preview LOGFALCON_WEB_PORT=8080 ./bin/logfalcon --web

Open http://localhost:8080 to see the dashboard’s Recordings, Updates and Settings pages. The local preview runs without a flight controller or Pi hotspot.

Build the image

With Docker running on macOS or Linux, run the following command from the root of your checkout.

bash pi-gen/build.sh --clean

Open the new run directory under pi-gen/deploy/. Check build-info.txt for the source revision and run shasum -a 256 -c checksums.txt there. Flash the verified .img.xz to a spare card.

The tag-triggered release workflow builds Linux ARM6, ARM64 and AMD64 binaries, builds and inspects the image, and checks required release assets.

See Contributing and the release checklist for further details.

CLI reference

logfalcon --web                              # Start the dashboard
logfalcon --port /dev/ttyACM0 --dry-run        # Copy; skip erasure
logfalcon --port /dev/ttyUSB0 --dry-run        # Explicit USB serial port
logfalcon --config /path/to/logfalcon.toml --web
logfalcon --version

A serial transfer requires an explicit --port. --dry-run still copies data and does not disable storage-pressure cleanup; configure that separately.
